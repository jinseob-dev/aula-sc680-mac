# SC680Config 1.0.13 (build 14)

- Correct the 8K DPI frame's Angle Snapping and Motion Sync fields. They were incorrectly populated with generic high-DPI bitmasks. Use the OEM defaults or preserve values from an imported Windows capture.
- Add the OEM 15-byte shared lighting/attribute command, verified against actual Windows blue and custom-color Apply captures.
- In Light, use Import Windows Lighting Capture to load sc680_hid_capture.log. Import reads settings locally and sends no USB commands. Apply Light changes only lighting while preserving the packet's other mouse attributes. The baseline is saved with the local profile.
- Explain the distinction between independent Steady/Breathe colors and DPI-mode stage colors. Brightness/speed use the OEM eight-step range.
- Compare generated DPI and lighting output byte-for-byte against captured Windows frames and test baseline persistence and rejected failed writes.

## Device verification

Windows Apply was confirmed to change colors immediately. Its capture shows RGB changes in command 0x05, and sensitivity changes in command 0x04. The Windows capture's stored DPI stage colors did not change. The Mac implementation now matches these observed command formats, but immediate application on the physical Mac-connected receiver still needs user verification. Full 8K configuration readback remains unavailable. No speculative initialization/reset/commit command is added.

## Try this build

Install the arm64 DMG. Open Light, import the existing sc680_hid_capture.log, select Steady or Breathe, set a clearly different color and click Apply Light. Check whether the LED changes immediately without pressing the DPI button. For stage colors, select DPI Steady or DPI Breathe in Light and apply that mode. Apply DPI now sends corrected control fields; verify numeric sensitivity separately.
